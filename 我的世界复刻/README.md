# Minecraft.js

纯浏览器的体素沙盒。地形、洞穴、矿脉、光照、贴图、音效**全部由代码实时生成**，不依赖任何外部素材文件（唯一外部依赖是从 CDN 加载的 three.js）。

---

## 怎么玩

### 方案一：双击 `minecraft.html`（推荐）

**单文件版，three.js 已内联，不需要 Node、不需要起服务器、不需要联网。**

### 方案二：跑多文件源码版

```
双击 Start_Game.bat        # 或 npm start
```

然后打开 <http://localhost:8080>。

`index.html` 是源码入口，**不能双击**——浏览器在 `file://` 下会用同源策略拦掉所有 ES 模块（双击只会看到一条指路提示）。

想换一个新世界：`http://localhost:8080/?seed=12345`

## 做了什么

### 世界生成
15 种生物群系，由**四张气候图**（大陆度 / 侵蚀度 / 温度 / 湿度）+ 地形高度共同决定：海洋、深海、沙滩、平原、森林、白桦森林、针叶林、沙漠、热带草原、丛林、沼泽、雪原、山地、裸岩山峰、河流。群系决定地表方块、植被种类与密度，以及草和树叶的染色。

地形高度 = 大陆度基准面 + 山脊噪声（按侵蚀度调制「山有多少」）+ 细节噪声，河网由另一条噪声下切出来。

### 洞穴与矿脉
两层 3D 噪声：空腔型（成片的大洞穴）+ 蠕虫型（两条噪声同时接近 0 时形成蜿蜒长隧道），靠近地表时自动收敛以免炸穿地面。y ≤ 12 的洞底填岩浆并发光。

六种矿脉按高度带随机游走成团：煤（y6–104）、铁（5–64）、金（4–32）、红石（4–24）、青金石（4–30）、钻石（3–16）。

### 光照
两条独立通道各自 BFS 泛洪：**天光**与**方块光**。

- 新区块生成后先做一次「天光柱状填充」——从顶往下逐格减光，竖直方向零成本且完全正确；随后的 BFS 只负责水平方向和跨区块边界。
- 洞穴内部是黑的，得自己带火把（萤石 15 级、火把 14 级、岩浆 15 级）。
- 拆掉光源会走**级联清除**；挖开一个洞会让天光灌进来。
- 昼夜只缩放天光，方块光不受影响。

### 渲染
区块网格化用**贪心合并**：贴图、4 角 AO、4 角光照、群系染色全一致的面才合并。合并后每个四边形内部仍保留 AO 渐变，观感与逐面渲染几乎一致，三角形数通常降一个数量级（实测 14000 实心格 → 约 2300 三角形）。

顶点 UV 是「平铺 UV」（合并出来的大于 1），片元着色器用 `fract` 重新映射回 16×16 图集里的那一格——这样既保住合并的收益，又只需要一张普通 2D 图集，不必上 `sampler2DArray`。代价是 mipmap 用不了（`fract` 会让屏幕空间导数在接缝跳变），所以统一 NearestFilter 关掉 mipmap，靠雾盖住远处锯齿。

另有：环境光遮蔽（AO）逐角计算并按四角和选择对角线修正各向异性、程序化贴图、程序化 WebAudio 音效、破坏碎屑粒子、昼夜循环、太阳月亮星星、径向淡出的云层、水下镜头染色。

### 交互手感
挖掘按原版那套模型算时间：

```
用对工具：t = 硬度 × 1.5 ÷ 工具速度
用错工具 / 徒手：t = 硬度 × 5
```

工具（木/石/铁/钻石，镐/斧/锹）有等级门槛——徒手挖不出铁矿石，钻石镐才挖得动钻石。破坏过程中每 0.22 秒响一次对应材质的音，碎了迸出碎屑、掉出物品、飞进背包。

## 代码结构

```
minecraft.html     ← 双击这个（单文件版，three.js 内联）
index.html         源码入口，需要 Start_Game.bat
build.mjs          打包脚本（esbuild）：src/ → minecraft.html
Start_Game.bat     Windows 一键起服务器
server.mjs         零依赖静态服务器
src/
  main.js           入口：装配各子系统 + 主循环
  core/
    constants.js    世界尺寸、视距、玩法速度
    noise.js        种子化 Simplex 2D/3D + fbm + ridged
    blocks.js       方块注册表（贴图/硬度/工具/掉落/光衰减/音效）
    items.js        工具与挖掘时间、掉落判定
  world/
    world.js        区块容器、方块读写、光照读写、存档
    generator.js    地形 + 洞穴 + 矿脉 + 植被
    biomes.js       群系表与选择规则
    light.js        天光/方块光 BFS 引擎
  render/
    tiles.js        贴图名 → 图集槽位（纯数据）
    atlas.js        程序化画出全部贴图 + 裂纹 + 工具图标
    mesher.js       贪心网格化（纯计算，不依赖 three）
    materials.js    自写着色器
    chunkRenderer.js 区块流式加载与网格生命周期
    sky.js          天空穹顶、太阳月亮星星、云、昼夜
    particles.js    碎屑粒子
  physics/
    raycast.js      体素 DDA 射线拾取
    player.js       扫掠 AABB 碰撞、游泳/飞行、自动上台阶
  ui/
    hud.js          准星、物品栏、调试信息
    mining.js       挖掘进度、裂纹叠加、放置
    inventory.js    背包
    drops.js        掉落物
    sounds.js       程序化音效
```

**分层原则**：`core/` 和 `world/` 完全不碰 DOM 与 three.js，`render/mesher.js` 也只输出平铺数组。把这条守住，才能在 Node 里整块跑单测。

改了 `src/` 之后重新生成单文件版：

```
npm install          # 只为了装 esbuild 和 three
npm run build
```

没装依赖时 `build.mjs` 会退化成「three 走 CDN」，产物需要联网。

## 性能

在 Node 22 上实测（每区块）：

| 环节 | 中位 | 平均 |
|---|---|---|
| 地形生成（含洞穴/矿脉/植被） | — | 10.3 ms |
| 光照初始化（天光柱填 + 泛洪） | — | 6.2 ms |
| 网格化（贪心合并） | 10 ms | 16.6 ms（最慢 67 ms） |

平均每区块约 1400 个三角形。

流式加载的预算按**毫秒**而不是按个数：单个区块的生成+光照+网格化接近 26 ms，按个数限流在慢机器上会直接掉帧，按时间限流则每帧额外开销有上限（游戏中 12 ms，停在菜单时 30 ms——反正没人操作，顺手把世界预加载好，点「进入世界」的第一帧面对的不是一片虚空）。

需要更远视距时按 `=` 调大；如果帧率不够就按 `-` 调小。

## 测试

不需要浏览器、不需要装依赖：

```
npm test              # 三套全跑
npm run test:logic    # 纯逻辑：噪声、生成、光照、网格化、物理、存档
npm run test:modules  # 模块图：import 路径、导出名、循环加载
npm run test:smoke    # 端到端：把整个游戏在 Node 里跑几百帧
```

`test/three-stub.mjs` 是 three.js 的最小替身，配合自定义 loader 让模块能在 Node 下被真实加载。

**重要提醒**：Node 替身只能覆盖「接线对不对」，覆盖不到 GLSL 和 WebGL 上传。这一版是靠 headless Chromium（SwiftShader 软件渲染）真跑一遍才发现下面三个 bug 的。

---

## 踩过的坑（都已在代码里注释）

1. **three 的 `ShaderMaterial` 只在 `uniformsNeedUpdate === true` 时才上传 `material.uniforms`**。该字段默认 `false`：不清这个标志，`uAtlas` 会一直是空纹理（采样得到 `(0,0,0,0)`），每个片元 `alpha=0` 被 `discard` 掉——**整个世界一个像素都渲染不出来，而控制台一条错误都没有**。昼夜、雾、水波时间这些每帧改的 uniform 同理全是冻结的。

2. **`getImageData` 返回的是 `Uint8ClampedArray`，而 WebGL 的 `texImage2D` 在 `type=UNSIGNED_BYTE` 时只接受 `Uint8Array`**。类型不对会让纹理上传静默失败、保持全零，同样表现为全黑。构造 `DataTexture` 前必须转一道。

3. **`BufferAttribute` 只接受 TypedArray**。网格化缓冲里是普通 JS 数组，直接塞进去会每建一个区块抛一次 `array should be a Typed Array`，世界一个三角形都出不来。`test/three-stub.mjs` 现在也照着 three 的行为做这个校验，让 Node 侧的测试能拦住这一类错。

另外两处值得一提的：

- **缠绕顺序**：`−X` 和 `+Z` 两个面的 `u` 向量指向坐标轴的**负方向**，贪心合并是沿坐标轴正方向推进的，两者不一致时合并出来的四边形会整体错位 `(w-1)` 格。`test/headless.mjs` 里有一条「每个本该可见的面必须被恰好一个四边形覆盖」的断言专门盯着它。
- **光照减光级联**：不能先 `set(0)` 再入栈——主循环第一轮读到的就是 0，`if (L === 0) continue` 会把起点跳过，清除链就此断掉，表现为「拆掉光源后光还亮着」。

## 已知限制

- 水面是整格的（挖开海岸不会出现半格水面）
- 没有生物、合成台、红石、流体传播
- 沙和砂砾掉落方块实体那部分留了字段但没实现
- 存档只存在浏览器 localStorage，换浏览器要重开
- 区块生成在主线程上（靠时间预算兜住了帧率；真要更大视距得挪进 Web Worker）
- 树冠内部的方块面因为天光被完全遮住而偏黑（原版也这样，但这里更明显一点）
